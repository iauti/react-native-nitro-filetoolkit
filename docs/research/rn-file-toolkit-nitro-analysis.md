# `rn-file-toolkit` → Nitro Modules research

Research cutoff: **2026-09-01**. This note is a source audit and planning input, not an implementation plan. It uses only the upstream repository/package metadata and official Margelo Nitro sources.

## Executive conclusions

1. **Rebuild the contract; do not mechanically port the TurboModule.** The upstream native spec reduces every structured input and output to `Object`, while the public wrapper reconstructs types with pervasive `any`. That discards the strongest reason to adopt Nitro: one statically generated, compile-checked contract across TypeScript, Swift, and Kotlin. See the [TurboModule spec](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/NativeFileToolkit.ts#L3-L37) and [public wrapper/types](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L22-L261).
2. **Use the first-party Nitro toolchain at `0.37.1`.** As of the cutoff, npm `latest` and GitHub's Latest release are `react-native-nitro-modules@0.37.1` and `nitrogen@0.37.1`, published/released on 2026-08-27. Start reproducibly with `npx nitrogen@0.37.1 init react-native-nitro-file-toolkit`, not an unpinned `@latest`. Sources: [Nitro 0.37.1 release](https://github.com/margelo/nitro/releases/tag/v0.37.1), [runtime package metadata](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/packages/react-native-nitro-modules/package.json#L1-L25), [Nitrogen package metadata](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/packages/nitrogen/package.json#L1-L41), and [official scaffold guide](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/getting-started/how-to-build-a-nitro-module.md#L17-L45).
3. **Model transfers as operations, not a Promise plus global events.** Nitro has retained callbacks but no built-in Promise/`AbortSignal` cancellation. A `DownloadTask`/`UploadTask` Hybrid Object can own `id`, snapshot/state, progress subscription, `wait()`, and explicit cooperative `pause`/`resume`/`cancel`; a persistent transfer manager can reattach background work by ID. Nitro documents callbacks as repeatable retained functions and Promises as async results, but the current Promise API has no cancellation surface. Sources: [callbacks/events](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/callbacks.md#L7-L57), [Promise contract](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/promises.md#L7-L79), and [C++ Promise source](https://github.com/margelo/nitro/blob/v0.37.1/packages/react-native-nitro-modules/cpp/core/Promise.hpp).
4. **Normalize platform semantics in native code.** The current API leaks raw Android/iOS status integers, offers background pause on iOS but not Android, returns different media/share/cookie shapes, and loses some iOS background options after process death. The new public contract needs portable enums, capability reporting, and explicit platform-specific fields rather than accidental numeric/string compatibility.
5. **Make all blocking I/O truly asynchronous and keep bulk bytes off strings.** Nitro methods are synchronous on the JS thread by default; filesystem, hashing, archives, and network operations therefore need native async execution. Use `ArrayBuffer` only for bounded binary exchange/stream chunks, with ownership rules observed, and use files/native task objects for large payloads. Nitro explicitly recommends async for heavy work and zero-copy `ArrayBuffer` for large binary data. Sources: [sync vs async](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/guides/sync-vs-async.md#L7-L104), [ArrayBuffer](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/array-buffers.md#L7-L124), and [performance guidance](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/guides/performance-tips.md#L118-L180).

## What the upstream library actually exposes

### Public JavaScript/TypeScript surface

The package exposes both named functions and a default namespace. Major groups are:

- transfers: `download`, `upload`, pause/resume/cancel download, background enumeration;
- JS-only queue: priority plus maximum concurrency;
- filesystem: exists/stat/read/write/append/copy/move/delete/mkdir/list/disk-space/hash;
- archives: zip/unzip;
- cache, base64/URL conversion, share/open;
- cookies and media-store/Photos saving;
- JS-only sessions;
- global download/upload lifecycle listeners;
- a React `useDownload` hook.

The declarations and wrapper implementations are all in one 1,100-line file. The exported option/result interfaces are visible in [lines 47–261](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L47-L261); the default namespace duplicates the named surface in [lines 1044–1100](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L1044-L1100).

The native codegen contract does **not** carry those types: all structured calls are `Object → Promise<Object>`, and the wrapper immediately casts the module to `any`. [Native spec](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/NativeFileToolkit.ts#L3-L37), [module fallback and `any`](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L16-L45).

### Native implementation strategy

- **Android background download:** system `DownloadManager`; IDs are persisted in `SharedPreferences`, progress is polled on the main looper every 1.5 seconds, and completion is observed through a dynamically registered broadcast receiver. [state/persistence](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L35-L139), [enqueue](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L315-L389), [poll/completion](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L589-L660).
- **Android foreground download/upload:** raw `HttpURLConnection` on ad-hoc Kotlin threads, with 8 KiB transfer buffers, fixed connect/read timeouts, limited manual redirects for foreground download, and fixed-length multipart upload. [download connection](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L258-L311), [foreground loop](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L391-L587), [upload](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1072-L1222).
- **iOS download:** foreground and background `NSURLSessionDownloadTask`s. Per-task dictionaries hold promises, options, retry state, resume data, and ID mappings behind a serial queue. [session/state initialization](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L9-L88), [download/control methods](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L238-L379), [delegates/retry](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L719-L1027).
- **iOS upload:** constructs a complete multipart body in a temporary file off-thread, then uses a foreground `NSURLSessionUploadTask`. [upload implementation](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1087-L1198).
- **Archives:** Android streams with `java.util.zip`; iOS ships a custom local-header ZIP parser/writer backed by system zlib. [Android zip/unzip](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1463-L1588), [iOS unzip/parser](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1436-L1673), [iOS writer](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1675-L1927).

## Semantic mismatches and correctness risks

### Downloads, queues, persistence, and controls

| Area | Observed behavior | Planning consequence |
| --- | --- | --- |
| Foreground vs background result | Foreground `download()` resolves at terminal completion; background resolves as soon as work is handed to the OS and terminal state arrives only through global events. [JS wrapper](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L359-L490), [iOS behavior](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L264-L288) | Do not overload one Promise with two meanings. Return a task handle consistently; `wait()` is terminal, while `start()`/construction acknowledges scheduling. |
| Queue semantics | The queue exists only in JS memory. Because a background native call resolves immediately after enqueue, its JS queue slot is immediately released; therefore `maxConcurrent` does **not** cap actual OS background transfers. High priority is LIFO (`unshift`), pending tasks have no cancellable handle, and queue state vanishes on reload/process death. [queue](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L263-L357), [background immediate result](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L349-L388) | Queue ownership must be native if it promises actual transfer concurrency or persistence. Define FIFO-with-priority ordering explicitly and let queued jobs be queried/cancelled by ID. |
| Pause/resume | iOS cancels a task and stores `NSURLSession` resume data for foreground or background work. Android only flips a flag around the foreground read loop; its `DownloadManager` path explicitly rejects pause/resume. [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L291-L353), [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L662-L699) | Either expose capabilities (`canPause`) and a portable `unsupported` error, or choose a cross-platform implementation that truly supports the promised behavior. Never silently imply parity. |
| Cancel | Both platforms report success even when no active job was found. Android cancellation settles a foreground download with `CANCELLED`; iOS uses `Cancelled`, and pause failure has another sentence. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L701-L727), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L355-L379) | Use a typed `FileToolkitError` code and make idempotence explicit (`cancel()` succeeds if already terminal, with snapshot telling the truth). |
| Background options | Android's background branch passes URL, headers, destination, and notification text to `DownloadManager` but does not implement requested retry or checksum. iOS options live in memory; after process relaunch it can recover `taskDescription` but not custom destination/name/checksum/retry. [Android branch](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L324-L388), [iOS recovery](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L754-L818) | Persist the complete normalized job record before starting background work and reconcile it at startup. Reject unsupported combinations rather than ignore options. |
| Reattachment | Android reloads persisted ID mappings but starts polling only when a new background download is enqueued; a completion broadcast received while the process is absent is not durably stored. iOS requires host `AppDelegate` forwarding for background-session completion. [Android init/poller](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L57-L139), [upstream iOS note](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/README.md#L734-L748) | Treat restart reconciliation and durable terminal results as first-class acceptance tests, including completion while JS is not running. |
| Status | `BackgroundDownloadInfo.status` is `number`; Android returns `DownloadManager` constants and iOS returns `NSURLSessionTaskState`. The README admits the raw values differ. [type](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L568-L579), [README](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/README.md#L739-L747) | Map platform states into one named enum and retain optional native diagnostic fields separately. |
| Hook lifecycle | `useDownload` keeps background state as `downloading`, but never listens for completion/error to update `result`/`status`; it also cancels the task on unmount, which conflicts with background survival. [hook](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L952-L1042) | Keep React hooks as a separate adapter over a durable task API. Unsubscribing UI must not cancel background work unless explicitly requested. |

There is also a race window: JS attaches background terminal listeners only after awaiting the native handoff. A very fast terminal event can arrive before those listeners exist. [listener timing](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L439-L481). A task snapshot plus durable terminal state removes reliance on event timing.

### Uploads

The README claims downloads **and uploads** survive suspension with automatic reattachment, but neither upload implementation is background/persistent: Android uses an in-process thread and iOS explicitly uses `fgSession`. There is no pause, cancellation, retry, background enumeration, or resume API for uploads even though an `uploadId` is returned. [claim](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/README.md#L49-L64), [Android upload](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1072-L1222), [iOS foreground upload](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1173-L1197).

Both sides stream the request body instead of holding the source file in RAM, which is good. Android writes the multipart body directly using fixed-length streaming; iOS first creates a second, complete temporary multipart file and then uploads it. Both accumulate the entire response body as a string. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1120-L1212), [iOS temp file](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1124-L1197), [iOS response accumulation](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1029-L1077).

The new design must decide whether v1 promises persistent uploads. If yes, use platform background-transfer facilities and persist request metadata. If no, name and document them as foreground tasks and reject `background: true` rather than advertising survival.

### Errors, results, progress, and cancellation

- Top-level functions generally swallow exceptions and return `{ success: false, error: string }`, while `fs.*` throws through `_ensure`; `df`, `hash`, and cookies still return result envelopes even inside `fs`. The package documents this split, but the split is incomplete and forces two handling styles. [wrappers](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L520-L704), [`fs` namespace note](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L770-L798), [default-export error note](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L1044-L1057).
- Errors are free-form, platform-dependent strings. There is no stable `code`, operation, path, URL, HTTP status, retryability, or native cause contract.
- Download progress is emitted per integer percentage in foreground Android, every 1.5 seconds for Android background, and at `NSURLSession` delegate cadence on iOS. JS estimates speed and ETA from event arrival time with exponential smoothing. Upload progress is only a percent. [Android foreground progress](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L449-L501), [Android background polling](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L589-L623), [iOS progress](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L721-L750), [JS speed/ETA](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/index.tsx#L359-L410).
- Archive, hash, copy/move, base64 conversion, and media-save operations have no progress or cancellation at all.

Nitro's native throws and Promise rejections propagate normally to JS. The clean baseline is therefore: reject exceptional failures with a normalized native error; return normal outcomes directly; reserve result unions for genuinely expected alternatives (for example, a user-cancelled share sheet). [Official error behavior](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/guides/errors.md#L7-L115).

### Filesystem and data semantics

| Area | Upstream behavior/risk | Required decision for the new contract |
| --- | --- | --- |
| Location model | All core methods accept raw filesystem path strings. Android public media returns `content://` on modern versions, while iOS often returns a path; neither the FS methods nor types distinguish the two. | Define an explicit `FileLocation`/URI policy. Do not pass a `content://` URI to an API that only accepts POSIX paths. State which schemes each operation supports. |
| “downloads” | Android's default is the app-specific external Downloads directory; iOS uses a sandbox Downloads directory/fallback. It is not necessarily the user's shared Downloads area. [Android destinations](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L192-L235), [iOS destinations](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L127-L163) | Rename scopes to precise concepts such as `cache`, `documents`, and `appDownloads`; expose public/media export separately. |
| Byte counts/timestamps | Public types use JS `number` for file sizes, downloaded bytes, disk capacity, and millisecond timestamps. | Use Nitro `Int64`/`UInt64` for byte counts and `Date` or explicitly named epoch values. Nitro maps these to native 64-bit integers rather than lossy JS doubles. [Nitro type table](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/typing-system.md#L45-L181) |
| Read/base64 | `readFile` loads the whole file and rejects over 50 MiB. Its error recommends “streaming or base64,” but base64 is itself whole-buffer and larger. Android caps `urlToBase64` at 50 MiB; iOS does not, despite the README claiming both do. [Android read](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L852-L890), [Android URL conversion](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1272-L1354), [iOS URL conversion](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1241-L1307), [README claim](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/README.md#L739-L747) | Keep bounded `readText`; offer bounded binary chunks/streams using `ArrayBuffer`; make base64 an explicit compatibility helper with a strict configurable maximum. |
| Listing/stat | `ls` returns bare names, while `stat` returns only path/name/size/modified/isDir; directory size is forced to zero. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L821-L850), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L490-L522) | Prefer one typed `FileInfo` with a portable `kind` enum, location, size, dates, and documented symlink behavior; let `list` return infos or provide a metadata option. |
| Move | Android falls back to recursive copy/delete across filesystems; iOS only calls `moveItem` and fails across volumes. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L945-L978), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L624-L648) | Specify overwrite, atomicity, cross-volume fallback, partial-failure cleanup, and directory support consistently. |
| Cache naming | `getCachedFiles` scans cache, documents, and downloads; `clearCache` clears toolkit cache **and documents** but not downloads. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L729-L802), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L381-L471) | Make scopes explicit: `listManagedFiles(scope?)`, `clearCache`, and `clearManaged(scope)` must match their names and never broaden deletion silently. |

Many Android and iOS FS methods execute the complete read/write/copy/hash/list operation synchronously inside the exported method before resolving a Promise; only selected network/archive/media operations dispatch themselves. Under Nitro, simply declaring `Promise<T>` is not sufficient—the native implementation must put blocking work inside `Promise.async`/a Task/coroutine/thread pool. [Android filesystem body](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L731-L1024), [iOS filesystem body](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L383-L692), [Nitro Promise threading](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/promises.md#L7-L76).

### Media, sharing, opening, and cookies

- `shareFile`: iOS resolves only after the share sheet completes and provides `completed`; Android resolves immediately after launching the chooser and never provides it. Android hardcodes chooser title `Share File`, while iOS ignores the supplied `title` and `subject`. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1356-L1403), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1332-L1380).
- `openFile`: Android uses MIME type to dispatch an intent; iOS ignores the argument and presents `UIDocumentInteractionController`. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1405-L1461), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1382-L1434).
- `saveToMediaStore`: Android supports typed public collections/albums and returns a content URI on Android 10+; iOS ignores `album`, puts images/videos into Photos, and merely copies audio/download files into Documents, returning a path. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1765-L1877), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L2089-L2151).
- Cookies are not equivalent. iOS can return domain/path/expiry/secure/HTTP-only from `NSHTTPCookieStorage`; Android parses a WebView `CookieManager` header string and fabricates the requested domain plus `/`, with no metadata. These stores also do not automatically establish that raw `HttpURLConnection` and `URLSession` transfers share identical cookie behavior. [Android](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1670-L1763), [iOS](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L2027-L2087).

These should be separate platform-aware services, not forced into falsely identical result structs. The portable core can return a discriminated outcome plus optional platform details.

### Archives and security

Both unzip implementations defend against path traversal/zip-slip. [Android canonical-path check](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/android/src/main/java/com/filetoolkit/FileToolkitModule.kt#L1465-L1523), [iOS standardized-path check](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1536-L1550).

The remaining archive risks are material:

- Android extraction streams data but has no per-entry, total expanded-byte, compression-ratio, entry-count, time, progress, or cancellation limit.
- iOS maps/loads the ZIP and inflates each deflated entry into `NSMutableData` before writing. It caps a declared per-entry uncompressed size at 512 MiB, but the unknown-size path grows an unbounded result buffer; there is no cumulative limit.
- The custom iOS reader handles only STORE and DEFLATE local headers, rejects STORE plus a data descriptor, silently skips unsupported methods, and is based on 32-bit sizes; ZIP64/encryption and other formats are not a portable promise. [iOS parser](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1478-L1673).
- The custom iOS writer likewise stores sizes/offsets/counts in 32-bit/16-bit ZIP fields and does not emit ZIP64. [iOS writer fields](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/ios/FileToolkit.mm#L1675-L1927).

The new module must define a supported ZIP profile and resource limits, clean partial output on failure/cancel, and test malicious archives. “Zero dependencies” is not worth a fragile custom parser unless that limited profile is deliberate.

### Required Nitro package shape

Current official guidance requires:

1. exact dev dependencies for generation (`nitrogen@0.37.1`, `react-native-nitro-modules@0.37.1` for this snapshot);
2. `react-native-nitro-modules: "*"` as an **optional peer**, allowing the consuming app to own the runtime version and preventing a second Nitro installation when a prerelease is used;
3. a root `nitro.json` with schema, C++ namespace, iOS module name, Android namespace/C++ library name, autolinking map, and ignored paths;
4. checked-in and published `nitrogen/generated` output—consumers must not run Nitrogen;
5. generated iOS autolinking Ruby loaded by the podspec, generated Android Gradle/CMake files included, and `registerAllNatives()` invoked from `JNI_OnLoad`;
6. default-constructible autolinked Hybrid Objects; parameterized objects should come from a factory Hybrid Object;
7. Kotlin implementation classes annotated `@DoNotStrip`.

Sources: [dependency policy and duplicate-runtime rationale](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/getting-started/how-to-build-a-nitro-module.md#L39-L64), [generated autolinking integration](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/getting-started/how-to-build-a-nitro-module.md#L71-L134), [`nitro.json`](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/getting-started/configuration-nitro-json.md#L6-L27), [autolinking constraints](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/getting-started/configuration-nitro-json.md#L136-L180), and [official package template](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/packages/template/package.json#L1-L78).

## Nitro type and performance rules for the new interface

- Define small input/output records as named TypeScript `interface`s in `*.nitro.ts`; Nitrogen makes them native structs and the TS spec becomes the source of truth. Prefer interfaces over object type aliases because TypeScript flattening can lose the symbol Nitrogen needs. [custom structs](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/custom-structs.md#L4-L108).
- Use named string unions for stable enums (`TransferState`, `FileKind`, `HashAlgorithm`, `ErrorCode`). Do not expose native integer states. Nitro statically generates native enums for named literal unions. [custom enums](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/custom-enums.md#L24-L60).
- Avoid `AnyMap`/`Object`, unnecessary variants, and very large eager structs/arrays. Struct fields are eagerly converted and arrays are deep-copied. [typing system](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/typing-system.md#L35-L195), [struct conversion](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/custom-structs.md#L103-L108), [large-data guidance](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/guides/performance-tips.md#L150-L230).
- Use `ArrayBuffer` for bounded raw chunks, not base64. A native-created buffer is owning and may live across threads; a JS-created non-owning buffer is only safe for the duration of a synchronous call unless copied first. Buffers are not thread-safe. [ownership/threading](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/types/array-buffers.md#L59-L124).
- Heavy work must return a Promise and dispatch internally. Cheap getters/snapshots may stay synchronous. The official rule of thumb is to make work async when it takes over 50 ms, but filesystem/network methods should be assumed blocking without needing a benchmark first. [sync/async guidance](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/guides/sync-vs-async.md#L41-L104).
- Swift/Kotlin are the pragmatic default for OS storage, content-URI, Photos, background-transfer, and lifecycle APIs. Use shared C++ only where a measured cross-platform hot path benefits (for example, a vetted byte transform/archive core); official guidance notes C++ avoids the extra Swift/Kotlin bridge. [performance guidance](https://github.com/margelo/nitro/blob/971d6ba3f8cef10d6175fe3bf7bc44a89a30ddf4/docs/docs/guides/performance-tips.md#L287-L293).

The repository has one Jest file with **six tests**: two queue tests, one session test, one generated-ID test, and two listener-lifetime tests. The native module is mocked. There are no Android/iOS native unit tests and no end-to-end assertions for actual downloads/uploads, process death, pause/resume, checksums, retries, filesystem behavior, archive compatibility/security, public media, cookies, sharing, or Expo integration. [test file](https://github.com/chavan-labs/rn-file-toolkit/blob/f41dcdc39147adedc560dd1895df41aefa597b72/src/__tests__/index.test.ts#L1-L190).

The Nitro replacement needs a platform contract matrix and native/integration tests before parity claims. Minimum high-risk suites:

- filesystem error/overwrite/atomicity/cross-volume/symlink/content-URI cases;
- foreground and background transfer lifecycle, including process kill/relaunch and completion with no JS listener;
- queue concurrency measured at the native transfer layer;
- cancel/pause/resume races and idempotence;
- redirect, timeout, 4xx/5xx, retry, checksum, unknown content-length, duplicate destination, and disk-full behavior;
- large files and bounded memory;
- malicious/corrupt/Zip64/encrypted/unsupported archives and cleanup after partial extraction;
- Android API 24/29/33/current and supported iOS versions;
- package tarball install, CocoaPods/Gradle autolinking, old/new architecture compatibility required by Nitro, and Expo development-build prebuild.

## Migration risks and plan gates

### High-risk behavioral changes

1. **Error model:** moving from `{ success, error }` to thrown/rejected typed errors is cleaner but breaking. If compatibility matters, implement it in a separate JS adapter; do not contaminate the native Nitro contract.
2. **Transfer return shape:** task handles replace background's immediate result and foreground's terminal result. A compatibility wrapper can retain `download(options): Promise<DownloadResult>`, but the core should not have a mode-dependent Promise meaning.
3. **Path/location model:** correcting `downloads`, `content://`, and Photos semantics will expose previously hidden platform differences. Migration docs need exact mapping.
4. **Background guarantees:** a trustworthy implementation needs durable metadata/results and host lifecycle integration. Do not mark v1 “background ready” until process-death tests pass.
5. **Queue ownership:** moving from JS to native changes when priority/concurrency are applied; this is necessary for the promised semantics but requires explicit ordering and persistence rules.
6. **Archive compatibility:** a safer implementation may intentionally reject formats the old iOS parser silently skipped. Publish the supported profile.
7. **Minimum versions:** Nitro 0.37.1 raises the effective floor to RN 0.75, Xcode 16.4/Swift 5.9, compileSdk 34, and NDK 27; upstream advertised RN 0.74 compatibility.
8. **Duplicate Nitro runtime:** the optional wildcard peer is not cosmetic. A non-optional/caret peer can install a second core and fail at runtime, especially with prereleases. Follow the 0.37.1 guidance exactly.

### Interface gates before implementation

The following decisions should be frozen in a short API specification before native work begins:

- supported schemes/location types and sandbox/public-media vocabulary;
- direct result vs exception policy and stable error-code taxonomy;
- `DownloadTask`/`UploadTask` lifecycle, listener disposal, snapshot model, cancellation idempotence, and restart reattachment;
- foreground/background feature matrix by platform, including pause/resume, retry, checksum, headers, cookies, overwrite, notification, and queue behavior;
- integer/time representation (`Int64`/`UInt64`/`Date`), progress units, throttling, and unknown-total behavior;
- overwrite/atomicity/recursive/symlink rules for every FS mutation;
- maximum in-memory read/base64/response/chunk sizes;
- archive format and anti-bomb limits;
- which features belong in the native core versus optional JS/React adapters (`useDownload`, sessions, legacy compatibility).

### Recommended implementation order

1. Scaffold/pin Nitro 0.37.1, establish package/autolinking/tarball CI, and compile a minimal registered root Hybrid Object on both platforms.
2. Freeze `.nitro.ts` domain types, normalized errors, paths/URIs, `FileInfo`, progress, and task interfaces; generate and check in bindings.
3. Implement the filesystem foundation with consistent semantics and native tests.
4. Implement native transfer registry/tasks, foreground download/upload, typed progress, cancellation, and native queueing.
5. Add background persistence/reconciliation one platform at a time with process-death integration tests.
6. Add archives with explicit limits and hostile fixtures.
7. Add media/share/open/cookies as capability-aware services.
8. Build a separate ergonomic JS layer (named exports and React hooks) and, only if required, a legacy `rn-file-toolkit` compatibility adapter.

This order prevents the current library's JS wrapper, global emitter, and inconsistent result envelopes from becoming the architecture of the new native core.
